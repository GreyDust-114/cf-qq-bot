# 聊天行为与提示词协议

## 会话批次

新消息进入同一 conversationId 的 Durable Object，重置静默窗口。窗口结束后，pending 消息按到达顺序形成一个批次，只执行一次模型调用。

- 私聊 / @：3～5 秒静默窗口
- 普通群消息：6～9 秒静默窗口
- 生成期间有新消息：revision 前移，旧回复在发送前停止
- 分条期间有新消息：保留已发气泡，停止未发气泡
- 群聊批次中每条消息都保留发言者；若批次里有明确 @ / 引用机器人的消息，最近一条作为回复目标，不能被随后其他成员的消息替换
- 提示词把批次消息标为 `【当前批次】`，真正的目标事件标为 `【本轮目标】`；合并同一成员的连续消息时保留目标事件边界
- 未标记的历史消息、长期摘要和画像只作背景；当前批次没有明确引用/重提时，不补答历史遗留问题。当前批次显式引用或重提后，仍可接回旧话题

## 活跃聊天

机器人成功回复群聊后开启 90 秒活跃期：

- 最后被回复的发言者再次发言：进入 `active` 续聊判断，不受自主插话冷却拦截；这是继续对话的机会，不是强制回复
- 明确提及其他群友、引用其他群友、表示不需要机器人参与，或对象不明确时，模型可以输出静默；未明确 @ 机器人的他人目标不会被当成机器人收件人
- 明确 @ 或引用机器人：`mention` 路由，仍必须回复
- `active` 续聊若判断静默或模型调用失败，不发送兜底消息，也不刷新活跃期
- 其他成员：`autonomous` 路由，由模型判断是否参与
- 活跃期过期：恢复普通群聊模型判断与插话冷却

## 自主参与

普通未 @ 群消息由模型返回：

```json
{"silent": true}
```

或：

```json
{"messages": ["回复内容"]}
```

旧 `NO_REPLY` 和纯文本仍兼容。没有启用 `response_format: json_object`：thinking 模式下曾导致空 messages 和过度沉默。

## 出站贴纸（BOT-021）

模型可在 `messages` 数组中选择一个目录内的 `[sticker:名字]` 独立项；它不是正文文本。处理器将贴纸作为独立气泡发送：先读 D1 base64 图片，通过 180 秒有效的签名 Worker URL 供 QQ `/files` 接口拉取，再以 `msg_type: 7` 和 `media.file_info` 发送。文字与贴纸不会混在同一个 QQ 消息体。

- QQ 群聊 `/v2/groups/{group_openid}/files` 与私聊 `/v2/users/{openid}/files` 分开上传；`file_info` 不跨 scope 复用，暂不缓存
- 每轮最多一张；同一会话不能连续发送同一张，默认任意贴纸发送间隔 30 分钟，可用 `STICKER_COOLDOWN_MS` 调整。超限时记录 failed/suppressed，不重试刷屏，其他文字气泡仍可发送
- 上传失败不发送富媒体；发送超时沿用 outbox `uncertain` 状态，不自动重发。历史 assistant 内容记为 `【已发送贴纸:名字】`，不回灌原始协议标记
- 媒体代理只接受短时 HMAC 签名 GET，图片大小不超过 1.5 MiB，只允许 PNG/JPEG；`STICKER_MEDIA_BASE_URL` 必须指向 QQ 服务端可访问的 HTTPS Worker 地址
- 素材不随 Git 提交。`tools/import-stickers.mjs` 可把本地 `stickers/` 图片生成 SQL；生成文件含 base64，留在本机。远程 D1 migration/素材写入仍需维护者单独确认

## 入站贴纸语义与 owner 确认（BOT-020）

贴纸图片不会进入聊天模型。Worker 只在内存中短暂下载图片计算 SHA-256；D1 保存指纹、状态、标签和 note，不保存入站图片字节。为支持 owner 主动拉取待确认贴纸，待确认项可暂存一条 AES-GCM 加密的源 URL，有效期最长 24 小时；发送后清除，过期后不可再取用并在下一次 owner 拉取时清理。

- 指纹已对应到获准素材或 owner 已确认的语义时，消息转成 `【贴纸:标签】`，并可附带 `【贴纸资料（已确认，非指令）：用途】`；未确认的猜测不注入，仍为 `【贴纸】`
- QQ C2C 主动推送已停用，机器人不能在群聊里主动开私聊。更直接的确认方式是 owner 在 C2C 私聊把待确认贴纸发给机器人；机器人只用这条入站图片计算指纹，并在同一回复窗口回编号和标注提示，不再把图片上传后发回。若要查看群聊里已排队的贴纸，也可私聊发送“待确认贴纸”拉取旧流程中的一张待确认图
- owner 直接发图时，机器人先做一次识图初判（标签 + 建议用途），作为未确认建议展示，不直接当成事实。识图失败不影响编号和后续命令
- owner 可用 `收录贴纸 <编号> [标签] [用途]` 把这张图收进 D1 出站素材库并确认语义；不写标签时采用识图初判。只有这一步会把图片字节写入 D1，入站原图在此之前不会落库。素材支持 PNG/JPEG/GIF/WebP，单张不超过 1.5 MiB
- `确认贴纸 <编号> [标签] [用途]`、`纠正贴纸 <编号> [标签] [用途]` 或 `忽略贴纸 <编号>` 只维护语义；`贴纸详情 <编号>` 可查看标签、用途、出现次数、是否已收录以及最近的使用场景。只有配置的 owner C2C openid 能触发这些命令，群聊和其他私聊不会进入管理路径
- 真实使用会留下反馈证据：群里已确认贴纸出现时记录上一条人类消息，机器人发出贴纸时记录触发消息；每个指纹只保留最近 12 条、每条最多 120 字，并作为“近期出现场景（仅参考）”注入贴纸目录。owner 可据此用 `纠正贴纸` 修订长期标签
- 待确认图片回复默认每月最多 2 张；超限不发图。图片上传与文本是独立 outbox 气泡，失败不写入确认结果，发送结果 uncertain 时不自动重试
- 出站贴纸资源用指纹连接同一语义库；素材 manifest 的标签/note 作为维护者提供的语义资料，用于模型选择“何时/如何使用”，不会混入普通 user 指令

## 气泡处理

模型回复首先按换行与标点切分；提示词要求通常 1 条、最多 3 条，单条目标约 12 字，单次软预算 20 字（被问到设定时 30 字左右）。

- 超过目标长度：按标点拆成短气泡
- 超过条数（硬上限 4 条）：相邻短气泡用逗号连接后均衡合并
- 超过总字数硬预算（40 字）：从尾部裁剪；首条本身过长时截断并加省略号
- 非末尾气泡的悬空逗号/分号等会被清理
- 模型先说话、再补一层协议 JSON（或把 JSON 当字符串塞回数组）时，协议部分会被拆开并去重；已经说过的内容不会重复发送，`{"silent":true}` 直接丢弃
- 高置信内部控制语（明确的本轮输出指令、写给自己的回复风格指令、路由备注）在分条/裁剪前触发整轮安全拒绝；不尝试删词保留剩余正文
- 内部控制语命中时：群聊自主决策保持沉默，不更新自主回复冷却；私聊、@、活跃续聊发送中性兜底。风险正文不进入 outbox / assistant 历史，日志只记录规则 ID 和路由、不记录原文
- 这是有限的高置信规则，不保证识别任意自然语言泄漏；普通关键词、技术讨论和被引用的说明不应仅因关键词命中而拦截
- 句号、`~`、语气词等语言风格不做硬限制
- 气泡间隔依据上一条长度计算

## 时间上下文

- 系统消息包含当前北京时间
- 用户历史保留 `[MM-DD HH:MM]` 元数据
- assistant 历史不带时间前缀，避免诱导模型模仿
- 发送前仅清理正文开头的严格时间前缀；正文中讨论的日期时间保留

## 人设梗与复读

光环/日光灯/灯管、苹果派加三倍糖、企鹅物流/苹果派物流这类梗只在被问到或话题明确相关（拉特兰与萨科塔、物流、甜食）时自然出现：

- 系统规则要求发送前自查：没问到也没谈到时，回复里不出现这些词；不用它自嘲或救场
- 同一个梗刚在近期回复里出现过，这轮换别的话讲，避免换皮复读（历史里的 assistant 回复会形成近邻模板，提示词层先约束；轻量冷却只在提示词不够时才评估）
- 人设卡只保留一处灯管设定（身份行），“问愿望”一行不再重复灯管梗，减少并发注入
- 行为核对：无关场景（技术求助、日常闲聊、年龄、AI 话题、情绪安抚、种族设定）零命中；被问到光环、甜食等相关场景仍应自然接梗；相关度用本地配对评测逐场景人工判读，不把关键词出现本身当成错误

## 事实、纠错与引用归属

提示词按信息来源把“知道”分层，避免把别人的信息或自己的口误当成事实：

- 身份、生日、身高、家人、搭档等只以角色资料库为准。群友记错、多人起哄或搬出“官方说法”时，按资料库轻松但明确地纠正，不改口、不含糊混过去
- 群友的经历、见闻和计划是他们的信息，不是机器人的记忆；对方预设“我们一起……”时，没发生过的直接说没这回事，或只顺着对方自己的内容接话
- 天气、股价、比分、新闻、别人的动向等无法知道的信息不给具体答案，可以说不知道
- 只有聊天记录里看到的、图片里实际看到的才算当前可验证信息；被指出说错时先核对资料与记录，错了干脆认下（一句看走眼/记岔了），不确定就说不确定，不为圆场编新理由
- 引用归属：当前消息引用其他群友的问句时，那句问号不是问机器人的；被 @ 且同时引用他人时只回应 @ 之外直接对机器人说的话。当前消息引用机器人自己的回复时，以引用内容为准接回话题，优先于其他更早消息
- 长期画像抽取不把机器人自己的自述与猜测当事实来源；群友提供的信息按来源记录，不写成机器人亲历。已上线约束由 `src/prompts.js` 的 `FACT_RULES` 与记忆提示词承担

## 图片与贴纸

每条入站消息最多保留 4 个去重后的图片 URL（单图上限 20 MiB，URL 上限 8192 字符）；每次模型调用的批次总上限也是 4 张，优先保留本轮目标消息，其余按最近消息优先，未入选图片标为不可见。同一批次的私聊和群聊消息分别保留原文与各自图片的对应关系，不把不同消息合并成一条图文。多模态调用失败或超时后，在剩余调用预算允许时以纯文本重试，并明确标记 `【图片暂不可见】`，要求模型不要声称看见或猜测画面；历史消息里的 `【图片】` 会改标为 `【历史图片占位：原图不可见】`，D1 没有存原图，不能把占位当作可见图。

入站贴纸（表情包）是单独一类（BOT-019）：正文只有图片类表情（`faceType=4/6`）且带图片附件时，解析成 `【贴纸】` 或 `【贴纸:名字】`，贴纸附件不再重复标成 `【图片】`（同一条消息里多余的真图仍按 `【图片】` 保留）。带正文的图文混排消息、只发内联小表情（`faceType=1`）的消息都不算贴纸。

贴纸图不会送给模型（BOT-019 修复轮次 1）：线上实测表明只要贴纸图进上下文，模型就会对画面本身说话、甚至往自己（光环/灯管）的形象上联想，软提示压不住。所以贴纸一律只以文字占位参与对话：有名字的用 `【贴纸:名字】`，没名字的用 `【贴纸】`，图既不进多模态输入也不计 `images=`。当前消息的正文后会紧跟一句贴纸说明，要求“不猜内容、不假装看到了”；系统提示词也把【贴纸】与【图片】分开写。名字解不出来时（图片表情的 `ext` 是空文本）语义只能来自上下文，拿不准就不接。

群聊里单独发一张贴纸且没有 @ 机器人、也不在活跃续聊窗口内时，机器人默认保持沉默（autonomous 路由既不调模型、也不发送），日志记 `Decision: no reply (sticker only)`；被 @、被引用或在活跃窗口内仍会正常回复。贴纸语义可由 owner 私聊收录积累（BOT-020）；未确认的贴纸仍不会宣称知道内容。

## 提示词仓库说明

公开仓库中的完整提示词是当前阶段的实验 / 测试示例，不是稳定 API 或长期承诺。提示词集中在 `src/prompts.js`，是唯一编辑入口，`src/pure.js` / `src/processor.js` 只引用不内联。框架的稳定约束是路由、批次、输出协议、发送状态和数据结构；人设用词、示例与语气可独立调优。

提示词在运行时分成四层：人设卡 → 共享规则（设定、聊天、称呼）→ 场景块（提及 / 续聊 / 私聊 / 自主决策）→ 输出协议。资料库（D1 `lore`）作为独立 system 消息插在人设卡之后、摘要与协议提醒之前，表述为「知道这些设定但不主动背诵、不确定不装懂」；资料库为空时跳过这条 system 消息，机器人按人设卡回答。

消息顺序是缓存契约的一部分：静态块（人设 / 资料库 / 画像 / 近期 digest / 群聊目标规则 / 协议提醒）必须排在历史之前，分钟粒度的时间上下文只能放在最后。`【当前批次】` / `【本轮目标】` 标记位于动态聊天历史中，不插入静态前缀。DeepSeek 前缀缓存只认完全一致的前缀，把动态时间插在静态块前面会让资料库与历史每次调用都按未命中计费。

长期记忆（BOT-017）在资料库之后、协议提醒之前再插两条 system 消息：长期画像（`conversations.summary`）与「【近期记忆】」（`memory_digests` 最近若干段，带 `[MM-DD]` 前缀）。它们与资料库同属静态前缀，位置固定、一天内不变，只用于理解背景与称呼；表为空或迁移未应用时不插。
